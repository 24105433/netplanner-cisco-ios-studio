    Learn the basics

    Everything you need for the exam, short. Click any highlighted command to copy it.

    1 · What an ACL does

    • An ACL is a list of permit and deny lines. The router compares a packet with the lines from the top; the first line that matches decides, the rest are skipped.
    • If no line matches, an invisible deny any at the end drops the packet.
    • An ACL does nothing until you apply it: ip access-group ID in|out on an interface, or access-class ID in on line vty for logins.
    • One ACL per interface per direction. Applying a second one replaces the first, so all rules for that port go in one ACL (the app does this).
    • It cannot filter traffic between two PCs in the same LAN (that never reaches the router).

    2 · Standard vs extended

    StandardExtended
    ChecksSource address onlyProtocol, source, destination, port
    Numbers1–99, 1300–1999100–199, 2000–2699
    Namedip access-list standard NAMEip access-list extended NAME
    Place itNear the destination (out)Near the source (in)
    Exampleaccess-list 10 deny 192.168.1.0 0.0.0.255access-list 100 deny tcp 192.168.1.0 0.0.0.255 host 192.168.2.10 eq 80

    Why the placement: a standard ACL can't see where a packet is going, so near the source it would block that source from everything. Extended can, so put it close to the sender and stop the traffic early.

    3 · Reading one extended line

    access-list 100 deny tcp 192.168.1.0 0.0.0.255 host 192.168.2.10 eq 80
    access-list 100ACL number 100 (100–199 = extended)
    denyDrop it (permit = let it through)
    tcpProtocol: ip = everything, tcp/udp = with a port, icmp = ping
    192.168.1.0 0.0.0.255Source: the whole 192.168.1.0/24 network
    host 192.168.2.10Destination: that one device
    eq 80Only destination port 80 (web)

    Read it as: "Block web from the 192.168.1.0/24 network to the server 192.168.2.10."

    5 · In or out?

    PC in LAN A→ g0/0 in→ Router→ g0/1 out→ LAN B
    • in = checked as the packet enters the router through that port (before routing).
    • out = checked as the packet leaves the router through that port.
    • Extended near the source → the sender's LAN port, in. Standard near the destination → the receiver's LAN port, out.
    • Think from the router's point of view, not the PC's.

    6 · Order and the hidden deny

    Task: only PC 192.168.1.10 may reach LAN B; the rest of LAN A may not.

    10 permit ip host 192.168.1.10 192.168.2.0 0.0.0.255
20 deny ip 192.168.1.0 0.0.0.255 192.168.2.0 0.0.0.255
30 permit ip any any
    • Swap 10 and 20 and the PC is blocked too: line 20 matches it first. Specific lines go on top.
    • Without line 30, everything else is dropped by the hidden deny any, even DHCP and ping replies.

    7 · Numbered vs named

    access-list 110 remark Block web
access-list 110 deny tcp 192.168.1.0 0.0.0.255 any eq 80
access-list 110 permit ip any any
interface g0/0
 ip access-group 110 in
    ip access-list extended BLOCK_WEB
 remark Block web
 deny tcp 192.168.1.0 0.0.0.255 any eq 80
 permit ip any any
 exit
interface g0/0
 ip access-group BLOCK_WEB in
    • Edit a numbered ACL: no access-list 110 deletes the whole list; paste it again (the app's scripts do this).
    • Edit a named ACL: ip access-list extended BLOCK_WEB, then no 20 removes line 20 and 15 deny … adds a line between 10 and 20.
    • Same rules, same result. Use what the task asks for (Settings → ACL IDs, or type the name on the ACL).

    8 · Login (VTY) ACL

    access-list 10 permit 192.168.1.0 0.0.0.255
line vty 0 4
 access-class 10 in
    • Only 192.168.1.0/24 may SSH or Telnet into the router; everyone else is refused by the hidden deny any.
    • Always a standard ACL, applied with access-class on line vty (not access-group).
    • Careful on a real router: if your own PC is not allowed, you lock yourself out of SSH (the console still works).

    9 · Check it on the router

    show access-listsEvery ACL with its lines and how many packets matched each (10 matches)
    show ip interface g0/0Look for "Outgoing/Inbound access list is …"
    show running-config | include accessThe ACL lines and where they are applied
    show running-config | section line vtyThe access-class on the VTY lines
    clear access-list countersReset the match counts before a test

    1. Reset every router (see Reset a router). Lab routers keep the last group's config.
    2. Cable it (see Cables). Write down which router port goes where; show cdp neighbors confirms it later.
    3. CPE 3105 final assessment? Use Exam setup at the top of the 1. Planner tab: type the exam's base networks in IPv4 Base Network & Mode and the IPv6 Planner (everything follows them), set the host counts, pick the routing scenario. It builds steps 3 to 5 for you; then follow the 7. Checklist tab from A to G and tick each step. If the topology on the day is different, change it in the Planner and Configure tabs: the scripts and the checklist follow. Come back to Exam setup to change the numbers, host counts, routing scenario, ISP or the ACL statements (a) to (d): Update this project keeps everything else you did.
    4. Your work is kept in this browser: close or reload the page and it opens where you left off (the first time it opens the exam for G1 S1). To move work to another PC, or keep a copy, use Save project.
    5. Planner tab: type the base network and prefix, add the routers (1941, 2901 or 2911), then one LAN row per LAN and one WAN row per router-to-router link. Pick the router and port for each row. Check the Generated Subnet Table.
    6. Topology tab: check the drawing: every router, LAN and link where you expect it, with its addresses. Click a router, then Show CLI.
    7. Configure & CLI tab: Init Config (passwords, banner, SSH/Telnet) → Routers & LANs (DHCP, DNS, IPv6 for each LAN) → Routing (the protocol the task asks for, per router). ACLs (only if the task asks) are on the 4. ACLs tab.
    8. CLI pane: pick a router, keep Copy in parts on, then for each part: Copy → right-click in PuTTY → wait for the prompt to come back → next part. Ticks show what you have pasted. Watch for % Invalid input.
    9. PCs: set them to DHCP (or the static values from the subnet table). See PC setup.
    10. Verify: click Verify in the CLI pane and run those commands. If something fails, open the Troubleshooting tab.
    11. Save: each script already ends with end + copy running-config startup-config (Init Config → Save at the end). At Destination filename [startup-config]? press Enter.

    Save the project (.json) when you finish the addressing, so you can reload it if the browser closes.

    Password recovery (old enable password unknown), 1941 / 2901 / 2911

    1. Turn the router off and on. Within the first 60 seconds send a Break: in PuTTY right-click the title bar → Special Command → Break. You get rommon 1 >.
    2. confreg 0x2142 then reset (boots and skips the saved config).
    3. Answer no to the setup dialog, then enable (no password asked).
    4. configure terminal → config-register 0x2102 → end (boots normally next time).
    5. erase startup-config → Enter, reload → no to save → Enter. The router comes back clean.

    Wireshark (Part IV): ICMP, Telnet and SSH

    Three captures, all on a PC: a ping between two LANs, a Telnet login and an SSH login. A switch only sends a PC its own traffic, so capture on the PC that pings or logs in.

    Before you start

    1. Open Wireshark and double-click the Ethernet adapter (the one with a moving line). Not Wi-Fi, not "Adapter for loopback traffic".
    2. Let the PCs answer pings: Windows Firewall drops them. Run the two netsh lines in PC setup → Firewall as administrator on both PCs.
    3. Pick pairs the ACLs allow, or capture before you paste the ACLs. With the exam ACLs: ping Downtown ↔ Laboratories (rule d allows it), Telnet from PC0, PC2 or PC4, SSH from PC8 or PC9 to Edge. The 7. Checklist tab (section G) names allowed pairs from your own rules.
    4. The Wireshark display filter is the green bar above the packet list: type the filter, press Enter. Green = valid, red = typo.

    1 · ICMP: Echo request and reply

    1. Start the capture (blue fin), filter icmp.
    2. Command Prompt: ping <IP of a PC in the other LAN>, e.g. ping 121.21.224.2.
    3. Stop (red square). Click an Echo (ping) request line. In the middle pane open: Internet Protocol Version 4 → Source and Destination; Internet Control Message Protocol → Type: 8 (Echo (ping) request).
    4. Click the matching Echo (ping) reply: Type: 0, and Source/Destination are swapped. Same Identifier and Sequence number = the pair.
    5. Screenshot both, then File → Save As icmp.pcapng.

    Only requests, no replies? The other PC's firewall, or an ACL that blocks the reply (ACLs tab → Packet tester). Filters to narrow it down: icmp.type == 8 · icmp.type == 0 · ip.addr == 121.21.224.2.

    2 · Telnet: the password in clear text

    1. Windows has no Telnet client until you turn it on (as administrator): dism /online /Enable-Feature /FeatureName:TelnetClient. Or use PuTTY with Connection type Telnet.
    2. Start the capture, filter telnet.
    3. From an allowed PC: telnet <router IP>, type the password, run show ip interface brief, then exit.
    4. Stop. Right-click any Telnet packet → Follow → TCP Stream. The window shows the whole session as text: the Password: prompt and the password you typed (your keystrokes in one colour, the router's in another).
    5. Screenshot the stream window, save telnet.pcapng.

    Each typed character is its own small packet, which is why the password also shows letter by letter in the packet list (Data field).

    3 · SSH: the same login, encrypted

    1. Start the capture, filter ssh (or tcp.port == 22).
    2. From an allowed PC: ssh -l admin <router IP>, accept the key (yes), type the password, show ip interface brief, exit.
    3. Stop. Follow → TCP Stream. Only the version lines are readable (SSH-2.0-Cisco-1.25 and the PC's); after the Key Exchange packets everything is random bytes. In the packet list the lines say Encrypted packet.
    4. Screenshot, save ssh.pcapng.

    Windows ssh says "no matching key exchange method" or "no matching host key type"? Older IOS offers older algorithms. Try:
    ssh -oKexAlgorithms=+diffie-hellman-group14-sha1 -oHostKeyAlgorithms=+ssh-rsa -l admin 121.21.225.5
    (change the IP), or log in with PuTTY (Connection type SSH). "Connection refused": SSH is not on (show ip ssh) or the login ACL refused this PC.
